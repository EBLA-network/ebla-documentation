# 🎱 Oracles

EBLA is EVM-compatible, so standard EVM oracle solutions can be deployed and used on EBLA. Here are a few EVM-compatible oracle options you can use.

## Stork

Stork is an oracle protocol that enables ultra low latency connections between data providers and both on and off-chain applications. The most common use-case for Stork is pulling and consuming market data in the form of real time price feeds for DeFi.

* Stork's [developer documentation](https://docs.stork.network/)
* How to [become a subscriber](https://docs.stork.network/getting-started/becoming-a-subscriber)
* [Stork's EVM contract addresses](https://docs.stork.network/resources/contract-addresses/evm)
* List of [asset pair IDs](https://docs.stork.network/resources/asset-id-registry) on the Stork oracle network

## blocksense

blocksense is a decentralized oracle network providing a suite of on-chain price feeds.

* blocksense [deployed contracts](https://docs.blocksense.network/docs/contracts/deployed-contracts)

## VIALabs

VIALabs is a cross-chain messaging and bridgeless cross-chain communication infrastructure connected to over 138 L1 and L2 networks, with tooling to build custom data oracles.

* VIALabs' [tech framework overview](https://developer.vialabs.io/general/technology-overview)
* How to set up a [private oracle for LLMs](https://developer.vialabs.io/examples/private-oracle)
* GitHub example: setting up a [weather data oracle](https://github.com/VIALabs-io/quickstart-oracle)
